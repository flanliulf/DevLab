## 1. 终端选择到底影响什么

herdr 自己不是终端模拟器，它是跑在你终端里的 TUI 客户端 + 后台 server。pane 里的画面由 herdr 内置的 VT 引擎（vendored 自 Ghostty）渲染，再交给外层终端显示。所以外层终端决定的是这几件事：

| 能力 | 影响 | 说明 |
|---|---|---|
| **真彩色（24-bit）** | herdr 主题、Claude Code / Codex 的 UI 配色 | Terminal.app 不支持，只能 256 色 |
| **鼠标事件上报** | herdr 是 mouse-first：点 pane、拖边框、右键菜单、拖选复制 | 主流终端都支持；VS Code 内置终端支持 |
| **Kitty 图形协议** | pane 内显示图片（agent 输出的截图、herdr-image 类插件、Claude Code 的 `[Image #1]` 预览） | herdr 只走 Kitty 协议（`terminal.kitty_graphics = true` 默认开），Sixel / iTerm2 协议不透传（issue #4330） |
| **键盘协议与按键映射** | `ctrl+b` 前缀、`ctrl+alt+*` 直达键、macOS 的 option 键 | herdr 文档说他们对照过 Ghostty、iTerm2、Terminal.app、kitty、WezTerm、Alacritty、Warp、Windows Terminal、GNOME Terminal、Konsole 的默认快捷键，并推荐 `ctrl+alt` 系列作为无现代键盘协议时也能传到的组合 |
| **通知与「聚焦回来」** | `[ui.toast] delivery = "system"` 时，点通知能否跳回 herdr 窗口 | macOS 走 terminal-notifier；Terminal.app、iTerm2、Ghostty、WezTerm 能聚焦已有客户端，iTerm2 / Ghostty / WezTerm 还能在标签页里开新客户端；Warp 不在支持列表（discussion #820） |
| **远程 TERM / terminfo** | 通过 `ssh` / `herdr --remote` / `machine add` 连宿主时，宿主上的程序认不认识你的 TERM | Ghostty 的 `xterm-ghostty`、Alacritty 的 `alacritty`、kitty 的 `xterm-kitty` 在远端缺 terminfo 时会报 `missing or unsuitable terminal` |
| **CJK 输入法** | 中文输入时光标位置、前缀键被输入法吃掉 | herdr 有 `experimental.reveal_hidden_cursor_for_cjk_ime` 与 `switch_ascii_input_source_in_prefix` 两个开关专门处理 |
| **粘贴图片给 agent** | Cmd+V 把剪贴板图片交给 Claude Code | 本地 pane 可用；经 `--remote` 曾有静默失败的 issue #205（已关闭），稳妥做法用 herdr-paste-image 插件把图存成文件再把路径打进 pane |

## 2. 逐个终端评估

| 终端 | 平台 | 真彩 | 鼠标 | Kitty 图形 | SSH 相关 | 与 herdr 搭配的结论 |
|---|---|---|---|---|---|---|
| **Ghostty** | macOS / Linux | 是 | 是 | 是 | 自定义 TERM `xterm-ghostty`；`shell-integration-features = ssh-env,ssh-terminfo` 自动处理；`ghostty +ssh` CLI（1.4+） | **首选**。herdr 的 VT 引擎就来自 Ghostty；社区文章与插件（herdr-hop）都以 Ghostty 为测试基线；原生标签/分屏、GPU 渲染、纯文本配置可进 dotfiles |
| **iTerm2** | macOS | 是 | 是 | 否（用自己的内联图片协议，herdr 不透传） | 标准 `xterm-256color`，零配置 | **成熟备选**。通知聚焦、标签开新客户端都支持；缺 Kitty 图形所以 pane 内不显示图片；tmux -CC 之类功能对 herdr 无意义 |
| **WezTerm** | macOS / Linux / Windows | 是 | 是 | 是（同时支持 Sixel、iTerm2 协议） | 内置 SSH 客户端 `wezterm ssh host`，读 `~/.ssh/config`，同一连接开新 tab 免重复认证；有自己的 mux server | **跨平台首选**，尤其 Windows 笔记本要连 Linux/Mac 宿主时；Lua 配置 |
| **kitty** | macOS / Linux | 是 | 是 | 是（协议原产地） | `kitten ssh host` 自动拷 terminfo + shell 集成 | 可用；默认快捷键 `ctrl+shift` 系与 herdr 不冲突；herdr-hop 等插件标注「理论支持未测试」 |
| **Alacritty** | 全平台 | 是 | 是 | 否 | TERM `alacritty`，远端可能缺 terminfo：`infocmp alacritty \| ssh host tic -x -` | 极简、无标签、无图片；适合当「专用远程窗口」（`alacritty -e herdr --remote mac-mini`），不适合当主客户端 |
| **Terminal.app** | macOS | **否** | 是 | 否 | 零配置 | 日常客户端不推荐（配色降级）；但**当宿主 Mac 上「登录项自动跑 herdr」的启动器很合适**：内置、随登录起、server 不需要好看 |
| **Warp** | macOS / Linux / Windows | 是 | 是 | 否 | 自带 SSH 工作流 | **不推荐**。Warp 定位是替代你的终端并自带 agent 平台；herdr 官方对比页把它归为「terminal app」一类；通知聚焦不支持；输入块模型对全屏 TUI 有历史兼容问题 |
| **VS Code / Cursor 内置终端** | 全平台 | 是 | 是 | 否 | 可配合 Remote-SSH 直接在宿主上开终端跑 `herdr` | 可用但要处理**快捷键冲突**：`ctrl+b` 是 VS Code「切换侧边栏」，需要把 `ctrl+b` 加进 `terminal.integrated.commandsToSkipShell` 的排除，或改 herdr 前缀；适合「编辑器里看一眼」而不是主控台 |
| **Windows Terminal** | Windows | 是 | 是 | 否（有 Sixel，herdr 不透传） | 配合 OpenSSH for Windows | Windows 客户端的默认选择；需要图片就换 WezTerm |
| **GNOME Terminal / Konsole** | Linux | 是 | 是 | GNOME 否；Konsole 22.04+ 是 | 标准 | Linux 桌面上够用；要图片选 Konsole、kitty、Ghostty、WezTerm |
| **foot** | Linux (Wayland) | 是 | 是 | 否（仅 Sixel） | 标准 | 图片不显示（issue #4330） |

### 2.1 推荐组合

| 角色 | 推荐 | 理由 |
|---|---|---|
| laptop（macOS 日常客户端） | Ghostty；次选 iTerm2 | Ghostty 与 herdr 血缘最近、图片可显示；iTerm2 最稳但无图 |
| laptop（Windows） | WezTerm；次选 Windows Terminal | 内置 SSH、图片协议全 |
| laptop（Linux 桌面） | Ghostty / kitty / WezTerm | 三者都全功能 |
| 宿主 Mac 上的 server 启动器 | Terminal.app 登录项（见指南二 §5.3） | 内置、可靠、从 GUI 会话起，Keychain 可用 |
| 「专用远程窗口」 | 任意能 `-e` 起命令的终端 | 见 §4 |
| 编辑器旁边看状态 | VS Code / Cursor 内置终端 + Remote-SSH | 改前缀或跳过快捷键 |
| 手机 | Moshi / Blink（mosh）、Redock、Termius | 见两份指南的手机章节 |

## 3. 各终端的远程 TERM / terminfo 处理（连宿主前必做一次）

### Ghostty

```
# ~/.config/ghostty/config
shell-integration-features = ssh-env,ssh-terminfo
```

- `ssh-terminfo`：连接时把 `xterm-ghostty` 的 terminfo 装到远端，远端程序可用全部 Ghostty 特性。
- `ssh-env`：转发若干环境变量并在装不上 terminfo 时回落到 `TERM=xterm-256color`。
- 两者通过在交互 shell 里包装 `ssh` 命令实现，所以**不作用于**脚本、`mosh`、`rsync -e ssh`、`git`、`sudo`、tmux 内、非交互 shell。这些场景用 `ghostty +ssh -- user@host`，或手动：

```bash
infocmp -x xterm-ghostty | ssh mac-mini -- tic -x -     # 一次性把 terminfo 装到宿主
# macOS Sonoma 及更早本机的 infocmp 太旧时：
/opt/homebrew/opt/ncurses/bin/infocmp -x xterm-ghostty | ssh mac-mini -- tic -x -
```

或者一劳永逸在 `~/.ssh/config` 里回落（OpenSSH 8.7+）：

```
Host mac-mini box
    SetEnv TERM=xterm-256color
```

- 远端 `sshd` 要有 `AcceptEnv` 才能收转发的变量；macOS / Ubuntu 默认接受 `LANG LC_*`，`TERM` 走 SetEnv 不受此限。
- 对 `herdr --remote` / `herdr machine add`：它们底层用的是系统 `ssh`，走 `~/.ssh/config`，所以 **SetEnv 或提前装好 terminfo 这两种方式都对 herdr 生效**，shell 包装那种不一定。

### kitty

```bash
kitten ssh mac-mini          # 自动拷 terminfo、shell 集成、支持文件传输
```

herdr 的远程连接不经过 kitten，所以同样建议提前 `infocmp -x xterm-kitty | ssh mac-mini -- tic -x -` 或 SetEnv。

### Alacritty

```bash
infocmp alacritty | ssh mac-mini -- tic -x -
```

### WezTerm

默认 `TERM=xterm-256color`，无需处理；要用 `wezterm` terminfo 的自行 `infocmp wezterm | ssh host tic -x -`。

### iTerm2 / Terminal.app / Windows Terminal / VS Code

默认 `xterm-256color`，无需处理。

## 4. 「专用远程窗口」的几种起法

指南二 §6.2 提到：本地终端若启动即 attach 本地 herdr，`herdr --remote` 会因嵌套被拒，且前缀键会被外层吃掉。解决办法是开一个**不跑本地 herdr 的窗口**专门连远程。按终端：

```bash
# Terminal.app（macOS 内置，最稳）
osascript -e 'tell application "Terminal" to do script "herdr --remote mac-mini"'

# Ghostty（macOS）
open -na Ghostty.app --args -e herdr --remote mac-mini
# Ghostty（Linux）
ghostty -e herdr --remote mac-mini

# Alacritty（macOS）
open -na Alacritty --args -e /bin/zsh -lc "herdr --remote mac-mini"

# WezTerm（任意平台；也可直接用它内置 ssh 再 attach）
wezterm start -- herdr --remote mac-mini
wezterm ssh mac-mini -- herdr

# kitty
kitty herdr --remote mac-mini
```

把其中一条做成 `~/bin/herdr-remote`，绑到 Raycast 或系统快捷键。若你用 0.9 的 `herdr machine add`，则不需要专用窗口，本地 herdr 侧边栏里直接切机器。

## 5. herdr 侧与终端相关的配置键

```toml
[terminal]
kitty_graphics = true          # 默认 true。外层终端不支持 Kitty 协议时可设 false 省资源；改后重启 server 或重连
default_shell = ""             # 空 = $SHELL
shell_mode = "auto"            # auto | login | non_login
new_cwd = "follow"

[ui.toast]
delivery = "system"            # macOS: terminal-notifier 优先，退回 osascript；点通知可聚焦 Terminal/iTerm2/Ghostty/WezTerm
# delivery = "terminal"        # 经外层终端发通知，SSH 场景可用

[experimental]
allow_nested = false                        # 需要在 herdr pane 里再开 herdr（如 --remote）时设 true
reveal_hidden_cursor_for_cjk_ime = false    # 中文输入法光标跟随问题时设 true（macOS）
cjk_ime_agents = []                         # 只对指定 agent 生效，如 ["claude"]
cjk_ime_cursor_shape = "steady_block"
switch_ascii_input_source_in_prefix = false # 按前缀键时临时切到 ASCII 输入源，避免中文输入法吃掉 prefix+x（macOS/Windows）
```

macOS 上用 option 作 alt 的 `ctrl+alt` 直达键，需要外层终端把 option 当 alt：Ghostty `macos-option-as-alt = true`；iTerm2 Profiles → Keys → Left Option key = Esc+；kitty `macos_option_as_alt yes`；WezTerm `send_composed_key_when_left_alt_is_pressed = false`。

## 6. 粘贴图片给 agent 的正确姿势

| 场景 | 做法 |
|---|---|
| 本地 herdr，Ghostty / kitty / WezTerm | 直接 Cmd+V，Claude Code 显示 `[Image #1]` |
| 本地 herdr，iTerm2 / Terminal.app | Cmd+V 通常也能进 Claude Code（它自己读剪贴板），但 pane 内不会渲染图片 |
| `herdr --remote` / `machine add` 远程 pane | 剪贴板在 laptop、进程在宿主，曾有静默失败（issue #205）。用插件：`herdr plugin install ddfonseca/herdr-paste-image`，配一个键（如 `prefix+i`）把剪贴板图片写到宿主 `~/.cache/herdr-paste-image/` 并把路径打进 pane；或自己 `scp` 后把路径贴给 agent |
| 想在 pane 旁边看图 / Mermaid / LaTeX | 社区插件 herdr-image、herdr-visuals、herdr-image-gallery（都要求外层终端支持 Kitty 协议） |

## 7. 不是终端但常被拿来比较的「agent 管理器」

这些是桌面应用或独立终端，思路是「替你管 agent 窗口」，与 herdr 的「后台运行时 + 任意客户端」路线不同。herdr 官方 /compare 页把它们分为 terminal app、process dashboard、manager app 三类，核心差异是：**关掉 UI 后 agent 还活不活**。

| 工具 | 形态 | 与 herdr 的关系 |
|---|---|---|
| cmux | macOS 原生终端应用，带 agent 状态提示 | 替代你的终端；关掉 app 会话即止 |
| Warp | 跨平台终端 + 自家 agent 平台 | 同上；见 §2 |
| Conductor / Crystal / Superset 之类 | 桌面 app，按 worktree 管理多个 Claude Code | 「manager app」；只在 app 打开时工作；无法 SSH 进去 |
| claude-squad / agent-deck 等 | tmux 之上的脚本层 | 保留 tmux 生态，但 agent 状态靠脚本猜 |
| VibeTunnel | 浏览器访问 Mac 终端 | 可与 herdr 叠加：浏览器里跑 `herdr` |
| Claude Code 桌面 App 的 Remote Control | 官方远程操控 Claude Code 会话 | 只覆盖 Claude Code 一种 agent；可与 herdr 并存 |

选型原则：只用 Claude Code 且只在一台 Mac 上，manager app 可能更省事；跨机器、多种 agent、要从手机/任何 tty 接入，herdr 这条路线才成立。
