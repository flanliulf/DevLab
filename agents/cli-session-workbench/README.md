# 多电脑、多账号的 Codex 与 Claude Code 会话工作台（CLI Session Workbench）

调研时间为 2026-11-19 至 2026-11-21，整理于 2026-11-23。本文记录已明确的个人使用需求、已有证据和待验证项，当前处于调研阶段。

## 一、统一术语（Glossary）

| 本文用词 | 含义 |
|---|---|
| 工作台 | 人用来找项目、读对话、发提示和看额度的统一界面。可以从不同电脑打开。 |
| 执行电脑 | 用来读写项目文件、运行命令和测试的 Mac 或 PC。预期用法是在这台电脑上运行官方 CLI；CC Desk Tunnel 另有一种安排，见第五节。同一台电脑也可以打开工作台。 |
| CLI | 命令行程序。本文特指官方 Codex CLI（`codex`）和 Claude Code CLI（`claude`）。执行电脑无需依赖两家的桌面应用。 |
| 后台程序 | 在执行电脑上连接工作台和 CLI 的程序。它启动或连接会话，传递提示、输出和审批结果。 |
| 项目、本地副本 | 项目指一个 GitHub 或 GitLab 仓库。本地副本指某台电脑上实际用于开发的目录。一个项目可以有多份副本，各自的分支和未提交修改可能不同。 |
| 会话、原生会话编号 | 会话是一段可以持续追问的对话。原生会话编号是 Codex 或 Claude Code 用来识别它的 ID。会话可以保留下来，当初的 CLI 进程可能已经退出。 |
| 原生记录 | CLI 自己保存、恢复会话时能够识别的记录。阅读旧消息和恢复 CLI 分别需要核实。 |
| 共享历史库 | 在原执行电脑之外保存对话的地方。获授权的新工作台可以从这里取回历史，即使它从未打开过这条会话。具体存放位置待选。 |
| 账号额度、会话消耗 | 额度指服务商报告的账号或组织使用上限，例如五小时窗口已用比例及重置时间。消耗指某次执行实际记录的 token 数量。两者分别展示。 |
| herdr 窗格 | Herdr TUI 终端界面里运行程序的一块区域。窗格可以关闭或改作他用；识别对话时还要核对 CLI 和原生会话编号。 |

## 二、按一天的使用过程说明需求（Daily Workflow）

### 上午，在办公室开始工作（Start a Session）

办公室 PC 和家里的 Mac 都有一份 `DevLab`。两个电脑可以登录同一个 Codex 账号，一台电脑上也可能同时配置个人和工作 Claude 账号。打开任何一台工作台，先按项目找到 `DevLab`，再看有哪些会话。列表可按电脑、CLI、账号和最近活动筛选。即使两个副本同名、分支也相同，每条会话仍显示自己的执行电脑和目录。

例如，选择「办公室 PC → DevLab → Claude 工作账号」，新建「排查登录失败」。工作台启动 PC 上的 CLI，记录执行电脑、项目目录、CLI、原生会话编号和本轮使用的账号。之后在聊天框输入「只重跑刚才失败的测试」，应送回这个目录里的这条会话。发送前就能看清目标电脑和计费账号。

### 下午，换屏幕看进度（Follow Live Work）

换到另一台电脑打开同一会话，先读到历史，再看到当前输出。需要看清提示是否送达、CLI 正在运行什么、工具返回了什么、是否等待批准，以及本轮最终完成、失败还是中断。可以在工作台继续追问、处理审批或停止执行。文字逐步显示只是其中一项体验。

两台工作台可以同时查看。在一端发出的提示和另一端完成的审批，都应出现在同一条时间线上。短暂断线后从上一次收到的位置补齐；若发送回执丢失，先核对原执行电脑是否收到。自动重发可能让同一条命令执行两次。

### 在执行电脑前，继续使用 herdr（Work in a Terminal）

今后的主要会话可以从工作台启动。坐在执行电脑前时，仍可用 Herdr TUI 同时管理多个终端 CLI。由 herdr 启动且有原生记录的会话也要归入项目历史，包括人在终端里补充的提示和 CLI 的回答。同一会话从两个入口被发现时，工作台只列一条。

第一版可以按实际能力分别显示「可读历史」「可恢复」「可实时操作」。对工作台启动的会话，实时输出和继续发送是核心需求。对普通终端或 herdr 中正在运行的 CLI，只有确认窗格仍对应同一运行实例、输入输出确实接通，才开放实时操作。任意终端启动后都能无缝接管，属于可选能力。

## 三、办公室 PC 关机，家里的新 Mac 仍能读完整历史（Offline History）

**第一版的关键场景是：办公室 PC 已关机，家里的 Mac 从未打开过这条会话。只要 Mac 能访问共享历史库，就应能按项目找到上周的会话，从头读到尾。** 只保存在办公室 PC 上，或者只缓存在曾经看过它的设备上，都无法满足这个场景。

| 时刻 | 用户应该得到的结果 |
|---|---|
| 首次接入办公室 PC | 在指定的项目和账号配置目录中发现已有的 Codex、Claude Code 记录，包括以前用 herdr 启动的会话。向共享历史库补入可读取的旧记录，标明成功、缺失或只保存了一部分。 |
| PC 在线工作 | 持续保存新增的提示、回答和 CLI 公开记录的工具调用、结果与审批。工作台关闭后，后台程序仍应能保存终端中新增的内容。 |
| PC 关机，新 Mac 首次访问 | Mac 从共享历史库取得会话列表和正文。分别显示电脑状态和保存状态，例如「办公室 PC 已离线 · 对话已保存至周五 18:20」。浏览历史无需启动 CLI。 |
| 突然断电，最后一段尚未保存 | 只能展示此前已确认保存的部分，标明已知的最后位置或时间。原电脑重新上线后，核对原生记录，补齐遗漏并消除重复。 |

**怎样算“完整”？** 用户应能找回第一条提示、中段的某一次追问及其回答、当时已记录的关键工具结果，以及最后一轮回复。工具输出可以折叠，但要能展开读取。原始记录已经截断、附件只有本地路径、部分记录无法解析或仍待同步时，应说明具体缺口。会话标题、摘要、最近若干条消息和终端截图都不能单独作为完整性的证据。

共享历史库承担阅读。原生会话记录仍承担 CLI 恢复。第一版需要确定历史保存范围、保留时间、哪些工作台可以读取，以及如何判断某条会话已保存完整。NAS、常在线的个人电脑和云端存储都是候选；所选位置必须在办公室 PC 关机时仍可访问。

## 四、原电脑上线，从同一个窗口回到原 CLI（Resume on the Original Computer）

1. **核对目标。** 办公室 PC 上线后，工作台核对电脑身份、实际项目目录、CLI 类型、原生会话编号和可用的账号配置。另一台电脑上即使存在同一个 Git 仓库，也应保留原执行位置。
2. **区分重新连接与恢复。** 如果只是关掉了工作台且 CLI 仍在运行，就连接已有实例，取回最新状态。如果 PC 已重启，旧进程已经结束。后台程序应在原目录和正确账号环境下，按原生编号恢复 Codex 或 Claude 会话，并核实恢复结果。
3. **再发送追问。** 确认目标后，将「继续分析上周那个失败的测试」送进已连接或已恢复的会话。其他工作台随后应看到同一条提示、回执和回答。恢复历史本身不能触发上一轮指令重跑。
4. **分别处理失败。** 原目录已移动、账号需要重新登录、原生记录已删除，或多个候选无法确定时，说明原因，保留已同步历史供阅读。若用户决定另开会话或更换执行电脑，应作为单独动作，避免把新对话显示成已恢复的旧会话。

**账号如何认定。** 用户在一台 Mac 上观察到，Claude Desktop 的列表可按账号和组织保存在 `~/Library/Application Support/Claude/claude-code-sessions/<账号ID>/<组织ID>/local_*.json`，两个账号的正文却都能出现在 `~/.claude/projects/<项目>/<会话ID>.jsonl`。这是特定环境的观察。其他电脑还可能使用不同的 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME`。工作台应分别记录「在哪里发现正文」「哪个账号的列表出现过它」「本轮将使用哪个账号」。目录名偶然包含账号 ID，或者今天登录了某账号，都不足以追认过去每一轮的计费身份。缺少证据的旧会话可以标为「历史账号未知」，照常阅读。

**额度如何显示。** 账号总览按服务商、已核实账号、组织或工作区及额度窗口归集。同一账号在 Mac 和 PC 上报告同一个窗口时，显示较新的有效读数及采样时间；各会话的 token 消耗仍可分别统计。输入框旁显示本轮账号、相关额度及重置时间。未取得额度时显示「未知」，旧数据标出更新时间。额度不足时向人说明，由人决定下一步；自动切号和自动重发不属于已确认的要求。

## 五、已验证的调研结论（Verified Findings）

本节的“已验证”指本次调研找到了相应的上游源码、官方文档或既有项目资料。使用者文章和帖子用于还原使用场景。各工具组合在个人真实账号与多机环境中的效果，单列于下一节。

**官方 CLI 已有供聊天界面使用的入口。** Codex 的 `codex app-server` 可以按编号恢复会话、开始一轮执行、返回增量输出和审批请求，也可以中断执行。Claude Code 支持用 `stream-json` 格式收发消息，并通过 `--resume` 恢复指定会话。本次调研时在一台 Mac 核对了 `codex-cli 0.132.0` 和 `Claude Code 2.1.327` 的命令帮助；这证明对应入口存在。提示能否正确送回指定 PC 上的既有会话，以及权限请求能否在另一台工作台完成，要通过第六节的场景检验。[Codex 官方协议](https://developers.openai.com/codex/app-server/) · [Claude Code 程序化运行说明](https://code.claude.com/docs/en/headless)

|---|---|---|

## 六、待验证的场景与选型判断（Open Validation）

以下为后续实机验收建议。本次只整理需求和调研，尚无多机端到端测试结果。

| 场景 | 建议怎样验证 | 通过条件 |
|---|---|---|
| **原电脑关机，新设备读完整历史** | 选一条超过 200 条消息、且中段有已知测试输出的旧会话。确认同步完成，关闭办公室 PC，用从未打开过该会话的 Mac 查看。Claude 和 Codex 分别验证，至少一条来自 herdr。 | 能找到同一项目，读到首条提示、中段问答、指定工具结果和最后一轮。已保存的附件可读；缺失内容准确标明。查看时无需原 PC 在线。 |
| **原电脑上线，恢复正确会话** | 重启 PC 后，在上述 Mac 的同一窗口追问中段测试，核对执行电脑、目录、CLI 编号和实际账号。另测原生记录缺失。 | 追问进入原 CLI 会话并只执行一次，结果返回两端。原生记录缺失时历史仍可读，界面说明恢复失败。 |
| **两台工作台同时查看与操作** | 从工作台启动任务，中途断开一端，在另一端处理审批，再重连。 | 新端先见历史，再接上实时输出；已处理的审批不会再执行。同一次发送回执丢失时可以核对结果。 |
| **herdr 与已有终端** | 在窗格内发一条工作台从未发送过的提示，再关闭、重用窗格。另找一条早于工作台安装的记录。 | 提示及回答被归入同一会话，旧记录可找回；窗格被重用后，消息不会错发给新进程。实测记录区分可阅读、可恢复和可实时接管。 |
| **同仓库、不同本地副本** | 分别使用 GitHub 和自建 GitLab，让 Mac 与 PC 各克隆一份，覆盖实际使用的 SSH 别名、HTTPS 地址及不同分支。 | 同仓库能归组，fork 或不同仓库不会因同名而混合；两处运行返回各自真实的目录与分支。 |
| **多账号与额度** | 同一个账号登录两台电脑，在其中一台再加另一个 Claude 或 Codex 账号。验证同机并行、共享旧目录、独立配置目录、过期及缺失读数。PC 按实际采用的原生 Windows 或 WSL（Windows 中的 Linux 环境）分别记录结果。 | 每次发送前能辨认执行账号；历史归属存疑时标为未知。同账号同窗口只显示一份额度，不同组织或窗口不误合并；不可用的读数有状态和时间。 |

**选型判断。** T3 Code 和 Paseo 可作为工作台候选。先用 T3 Code 核对多账号和额度，再用相同样例比较两者的跨机归组、历史完整性和原机续聊。herdr 是日常终端入口与后台运行方式的参考，CC Desk Tunnel 是终端记录归集、异机保存和原生恢复的参考。最终选型取决于上表前两项能否同时通过。共享历史库的位置、访问权限、保留期限以及是否需要额外补充历史同步能力，留待验证后决定。
