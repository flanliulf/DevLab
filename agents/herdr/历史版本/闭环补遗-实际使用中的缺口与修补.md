# 闭环补遗：按「一天的实际使用」逐步推演后发现的缺口与修补

> 方法：把两个场景各按「初始化 → 接入 → 派任务 → agent 运行 → 审批 → 完成验收 → 收尾 → 无人值守期间 → 升级/重启」九步走一遍，核对前三份文档每一步是否可执行。下面每个缺口都给出可直接执行的修补。整理日期 2026-09-23。
> 编号与正文对应：A–H 主要影响 Linux 场景，I–M 主要影响 Mac 场景，C/D/E/F/H 两个场景通用。

## A. Agent 登录与配额

### A.1 无头登录

```bash
# Claude Code：交互登录会打印 URL，在笔记本浏览器完成后把授权码贴回；或直接用 API key
claude            # 首次运行按提示
# 或
export ANTHROPIC_API_KEY=sk-ant-...   # 放进 ~/.config/agents.env（见 B）

# Codex：设备码登录，适合无浏览器主机
codex login --device-auth
# 或 API key
export OPENAI_API_KEY=sk-...
```

macOS 宿主上 Claude Code 的 OAuth 凭据存在 login Keychain，所以**登录动作要在 GUI 会话里做**（屏幕共享进去，在 herdr 的 pane 里跑 `claude`），否则 SSH 会话里登录成功、pane 里却读不到（见 K）。

### A.2 配额与并发预算

- 同一账号下的多个 Claude Code 实例共享订阅的用量窗口；一次开 5 个 agent 很容易在一两个小时内触顶，之后全部 agent 一起等待。
- 建议：先跑 2–3 个观察 `claude` 里的 `/usage`；把长任务错峰；关键 agent 用 API key 走按量计费与订阅隔离；Claude Code 的 Notification hook 有 `quota_auto_resume_*` 类型，可以接进 ntfy（指南一 §9.1 的脚本把匹配器扩成 `permission_prompt|agent_needs_input|agent_completed|idle_prompt|quota_auto_resume_fired`）。
- Codex 同理，注意组织级速率限制。

## B. PATH 与环境变量（Linux）

问题：Debian/Ubuntu 默认 `~/.bashrc` 顶部有 `case $- in *i*) ;; *) return;; esac`，`ssh box 'herdr agent list'` 这类非交互命令会在这一行退出，拿不到后面 export 的 `~/.local/bin`、mise、API key。指南一 §5.2 提到的 `~/.config/environment.d/` 只对 systemd 拉起的进程生效，**herdr-server 不是 systemd 拉起的，这条不成立**，已在指南一修正。

修补：

```bash
# 1. 统一放一个文件
cat > ~/.config/agents.env <<'EOF'
export PATH="$HOME/.local/bin:$HOME/.local/share/mise/shims:$PATH"
export LANG=en_US.UTF-8
export ANTHROPIC_API_KEY=...
export OPENAI_API_KEY=...
export GH_TOKEN=...
EOF
chmod 600 ~/.config/agents.env

# 2. 在 ~/.bashrc 的交互判断「之前」和 ~/.profile 里都 source 它
sed -i '1i [ -f "$HOME/.config/agents.env" ] && . "$HOME/.config/agents.env"' ~/.bashrc
echo '[ -f "$HOME/.config/agents.env" ] && . "$HOME/.config/agents.env"' >> ~/.profile
```

验证：

```bash
ssh box 'which herdr claude codex; echo $ANTHROPIC_API_KEY | cut -c1-8'
```

herdr pane 里的 shell 是交互式的（`shell_mode = auto`），会读 `.bashrc`，因此 pane 内的 agent 也能拿到同一份变量。用 mise shims 而不是 `mise activate`，是因为 shims 在非交互场景也生效。

macOS 宿主对应做法：写进 `~/.zshenv`（zsh 在所有模式都读它），不要写在 `.zshrc`。

## C. worktree 的依赖、环境文件与端口

`git worktree add` 只带受版本控制的文件。修补 `new-task` 脚本，在起 agent 前准备好环境：

```bash
#!/usr/bin/env bash
# new-task <repo> <branch> [agent-kind] [prompt]
set -euo pipefail
repo=$1; branch=$2; kind=${3:-claude}; prompt=${4:-}
src=~/src/$repo

created=$(herdr worktree create --cwd "$src" --branch "$branch" --no-focus)
pane=$(printf '%s\n' "$created" | jq -r '.result.root_pane.pane_id')
wt=$(printf '%s\n' "$created"   | jq -r '.result.workspace.cwd // empty')
[ -z "$wt" ] && wt=$(git -C "$src" worktree list --porcelain | awk -v b="refs/heads/$branch" '$1=="worktree"{p=$2} $1=="branch"&&$2==b{print p}')

# 1. 环境文件：从主 checkout 拷贝未跟踪的本地配置
for f in .env .env.local .envrc; do [ -f "$src/$f" ] && cp "$src/$f" "$wt/$f"; done

# 2. 端口：给每个 worktree 分配唯一端口，写进 .env，避免多个 dev server 撞车
port=$(( 3000 + $(echo "$branch" | cksum | cut -d' ' -f1) % 1000 ))
printf '\nPORT=%s\n' "$port" >> "$wt/.env"

# 3. 依赖：优先 pnpm（共享 store，省磁盘），否则 npm ci
if [ -f "$wt/pnpm-lock.yaml" ]; then (cd "$wt" && pnpm install --frozen-lockfile)
elif [ -f "$wt/package-lock.json" ]; then (cd "$wt" && npm ci); fi

name=$(echo "$branch" | tr -c 'a-z0-9_-\n' '-' | cut -c1-30)
herdr agent start "$name" --kind "$kind" --pane "$pane"
[ -n "$prompt" ] && herdr agent prompt "$name" "$prompt"
echo "$name -> $wt (PORT=$port)"
```

要点：
- 仓库里加一份 `.env.example`，并把「本地配置从哪来」写进 CLAUDE.md，agent 自己也会照做。
- 端口用 `PORT` 环境变量是多数框架的约定；不认 `PORT` 的框架在 CLAUDE.md 里写明启动命令要带 `--port $PORT`。
- Node 项目统一用 pnpm 可以让 N 个 worktree 共享一个 store，磁盘从 N 倍降到接近 1 倍（见 H）。

## D. 权限策略：让 agent 少 blocked，但不失控

这是远程场景能否跑起来的关键。目标：常规安全操作自动放行，危险操作仍然 blocked 并推到手机。

### D.1 Claude Code

仓库级 `.claude/settings.json`（进版本库，团队共享）：

```json
{
  "permissions": {
    "allow": [
      "Read", "Edit", "Write", "Glob", "Grep",
      "Bash(git status*)", "Bash(git diff*)", "Bash(git log*)", "Bash(git add*)", "Bash(git commit*)",
      "Bash(git push origin HEAD*)",
      "Bash(npm test*)", "Bash(npm run *)", "Bash(pnpm *)", "Bash(just *)",
      "Bash(pytest*)", "Bash(cargo test*)", "Bash(go test*)",
      "WebFetch(domain:docs.*)"
    ],
    "deny": [
      "Bash(git push --force*)", "Bash(git push * main)", "Bash(git push * master)",
      "Bash(rm -rf *)", "Bash(sudo *)", "Bash(curl * | sh)",
      "Read(./.env)", "Read(./secrets/**)"
    ]
  }
}
```

- 启动时也可以 `claude --permission-mode acceptEdits`：文件编辑自动放行，Bash 仍逐条询问。
- `--dangerously-skip-permissions` 只在容器/沙箱里用（指南一 §10）。
- 仍会 blocked 的就是真正需要人的：删除、强推、装依赖、访问未知域名。这些通过 ntfy / moshi-hook 推到手机，用 `herdr pane send-keys <pane> enter` 或 Moshi 卡片批。

### D.2 Codex

```bash
codex --ask-for-approval on-request --sandbox workspace-write     # 常规：可写工作区，出工作区/联网才问
codex --ask-for-approval never --sandbox read-only                 # 只读评审 agent
```

或写进 `~/.codex/config.toml` 的 `approval_policy` / `sandbox_mode`。评审型 agent 用只读模式，永远不会 blocked。

### D.3 给无人值守 agent 的仓库规则

在每个仓库根放 `CLAUDE.md`（Codex 读 `AGENTS.md`，内容可相同）：

```markdown
# 无人值守规则
- 只在当前 worktree 的分支上工作，禁止切换到 main / 禁止 force push。
- 每次改动后运行 `npm test`；测试不过不要提交。
- 完成后：`git add -A && git commit -m "<类型>: <摘要>"`，然后 `git push origin HEAD`，最后 `gh pr create --fill --draft`。
- 需要新依赖、删除文件、访问外部服务时先停下来询问。
- 本地配置来自 .env（已由脚本准备），启动开发服务器必须使用 $PORT。
```

### D.4 从手机批审批的安全习惯

- 先 `herdr pane read <pane> --source visible --lines 20` 看清在批什么，再 `send-keys enter`。
- Claude Code 的审批提示里「Yes, and don't ask again for this session」慎用；用 D.1 的 allow 列表替代。

## E. git 推送与提交身份

pane 里的进程由 herdr-server 派生，**没有你笔记本的 `SSH_AUTH_SOCK`**，所以 `git push` 走 SSH 会失败。三选一：

```bash
# 方案 1（推荐）：gh 的 HTTPS token，Linux 存文件、macOS 存 Keychain
gh auth login --git-protocol https
gh auth setup-git

# 方案 2：主机本地专用 deploy key（只给需要的仓库，可只读或读写）
ssh-keygen -t ed25519 -f ~/.ssh/id_agent -C "box-agent"
# 在 GitHub 仓库 Settings → Deploy keys 添加 ~/.ssh/id_agent.pub（勾 write 才能 push）
cat >> ~/.ssh/config <<'EOF'
Host github.com
    IdentityFile ~/.ssh/id_agent
    IdentitiesOnly yes
EOF

# 方案 3：细粒度 PAT 放 GH_TOKEN（B 的 agents.env），gh 与 git 自动使用
```

提交身份与签名：

```bash
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
# 要求签名的组织：用 SSH 签名，密钥就是上面的 id_agent
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_agent.pub
git config --global commit.gpgsign true
```

macOS 宿主注意：`gh` 用 osxkeychain 存 token，同样要求 server 在 GUI 会话（K）。

## F. 完成后的收尾

一个任务的标准收尾（可做成 `done-task <name>`）：

```bash
#!/usr/bin/env bash
set -euo pipefail
name=$1
info=$(herdr agent list --json | jq -r --arg n "$name" '.result.agents[] | select(.name==$n)')
ws=$(echo "$info" | jq -r '.workspace_id')
wt=$(herdr workspace list --json | jq -r --arg w "$ws" '.result.workspaces[] | select(.workspace_id==$w) | .cwd')
repo=$(git -C "$wt" rev-parse --show-toplevel)
main=$(git -C "$wt" worktree list --porcelain | awk '$1=="worktree"{print $2; exit}')
branch=$(git -C "$wt" branch --show-current)

# 1. 验收
git -C "$wt" status --short
git -C "$wt" log --oneline "$(git -C "$main" branch --show-current)..HEAD"
# 2. 确认已推送 / 已合并（人工看 PR 之后再继续）
read -r -p "已合并并可删除 $branch? [y/N] " ok; [ "$ok" = y ] || exit 0
# 3. 关闭 workspace（里面的 agent 进程随之结束）
herdr workspace close "$ws"
# 4. 删 worktree 与分支
git -C "$main" worktree remove "$wt" --force
git -C "$main" branch -d "$branch" || true
git -C "$main" worktree prune
```

JSON 字段名以你机器上 `herdr api schema --json` 为准。每周跑一次 `git worktree prune` 和 `herdr workspace list` 清理遗留。

## G. 无人值守期间的两个定时炸弹（Linux）

### G.1 unattended-upgrades 自动重启

Ubuntu 默认装了 unattended-upgrades，内核更新后若配置了自动重启，会在凌晨杀掉所有 agent。

```bash
sudo sed -i 's|^//Unattended-Upgrade::Automatic-Reboot "false";|Unattended-Upgrade::Automatic-Reboot "false";|' /etc/apt/apt.conf.d/50unattended-upgrades
grep Automatic-Reboot /etc/apt/apt.conf.d/50unattended-upgrades    # 确认为 "false"
```

需要重启时手动选时间：`sudo reboot`，然后 `herdr` 恢复布局与会话。

### G.2 Tailscale 节点密钥过期

节点密钥默认 180 天过期，过期后节点掉线、远程直接断。宿主类节点在 Tailscale 管理台（Machines → 该机器 → Disable key expiry）关闭过期。手机、笔记本这类客户端保留过期即可。

## I. 离开宿主 Mac 之前必须到场完成的事（Mac）

这些操作要么弹图形对话框，要么要输一次本机密码，SSH 里做不了：

- [ ] `xcode-select --install`（git 依赖它；弹窗确认）
- [ ] 安装 Homebrew（要 sudo 密码）
- [ ] 系统设置：远程登录、屏幕共享、节能、自动登录（或决定 FileVault 策略）
- [ ] 隐私与安全性 → 完全磁盘访问：勾选 **Terminal** 和 **远程登录**（sshd）（见 J）
- [ ] 隐私与安全性 → 自动化：允许 Terminal 控制系统事件（osascript 需要）
- [ ] 在 Terminal 里跑一次 `herdr`，并在 pane 里完成 `claude`、`codex`、`gh auth login` 的登录（凭据进 Keychain，见 K）
- [ ] Terminal → 设置 → 描述文件 → Shell → 启动时运行 `herdr`；登录项加入 Terminal
- [ ] 软件更新：关闭「自动安装 macOS 更新」（见 M）
- [ ] 重启一次，验证自动登录 → Terminal 自启 → `herdr status server` 正常，再离开

## J. macOS TCC：SSH 与 Terminal 访问受保护目录（Mac）

现象：`ssh mac-mini 'ls ~/Documents'` 报 `Operation not permitted`；agent 在 pane 里读 `~/Downloads/spec.pdf` 失败。原因是 macOS 的 TCC 对 Desktop/Documents/Downloads、iCloud、可移动卷做了保护。

修补两条同时做：
1. **仓库放在非受保护目录**：`~/src`、`~/wt` 不受 TCC 限制。本套文档一直这么约定。
2. **授予完全磁盘访问**：系统设置 → 隐私与安全性 → 完全磁盘访问 → 打开「远程登录」和「Terminal」（Terminal 首次访问时也可能弹窗，用屏幕共享点「允许」）。

## K. Keychain：为什么 server 必须从 GUI 会话启动（Mac）

依赖 login Keychain 的东西：Claude Code 的 OAuth 凭据、`gh` 的 token（osxkeychain）、1Password CLI、moshi-hook 配对、部分 npm 私有源凭据。SSH 会话拿不到已解锁的 login Keychain，从 SSH 拉起的 herdr-server 及其所有 pane 都继承这个缺陷，表现为 agent 反复要求登录、`gh` 报未认证、`security` 报 `User interaction is not allowed`。

修补顺序：
1. 指南二 §5.3 的「Terminal 登录项自动跑 herdr」是**硬性前置**，不是可选项。
2. 判断当前 server 是不是 GUI 会话起的：在任一 pane 里跑 `security find-generic-password -s nonexistent 2>&1 | head -1`，出现 `could not be found` 正常，出现 `User interaction is not allowed` 说明 server 在 SSH 会话，需要 `herdr server stop` 后从 Terminal 重起。
3. 应急：SSH 里 `security unlock-keychain ~/Library/Keychains/login.keychain-db` 可临时解锁给当前会话用，但不改变已运行 server 的状态。
4. 宿主重启后，先等自动登录 + Terminal 自启把 server 起好，再从 laptop 连；若 laptop 的 `herdr machine add` 先到，它会经 SSH 拉起一个没有 Keychain 的 server。可在 laptop 侧用 `ssh mac-mini 'herdr status server'` 确认后再 attach。

## M. macOS 自动更新会重启宿主（Mac）

系统设置 → 通用 → 软件更新 → 自动更新 → 关闭「安装 macOS 更新」，保留「安全响应与系统文件」。需要升级时手动：

```bash
ssh mac-mini 'sudo softwareupdate -l'
ssh mac-mini 'sudo softwareupdate -i -a'          # 不带 --restart
ssh mac-mini 'sudo fdesetup authrestart'          # FileVault 开着时用这个重启
```

## 修订后的两条完整流程

### Linux 场景一天

1. 早：`ssh box 'herdr agent list'`（PATH 已由 B 保证）或本地 `herdr` 看 VPS 侧边栏。
2. 派任务：`new-task app fix/login-timeout claude "修复登录超时，见 issue #123"`（C 已备好 .env、端口、依赖）。
3. agent 运行；常规操作因 D 的 allow 列表不再询问；真正需要人的操作推到手机，先 `pane read` 再 `send-keys enter`。
4. done：agent 按 CLAUDE.md 自己 commit / push / 开草稿 PR（E 已配好凭据）。
5. 验收：看 PR，跑 CI，合并。
6. 收尾：`done-task fix-login-timeout`（F 关 workspace、删 worktree）。
7. 夜里：unattended-upgrades 不再重启，Tailscale 不过期（G），磁盘有清理（H）。

### 两台 Mac 一天

1. 前提：I 清单已在到场时完成，J/K/M 已处理。
2. laptop `herdr`，侧边栏切到 Home Mac mini；派任务用 `herdr-mm` 前缀执行同样的 `new-task`。
3. 运行与审批同上，手机端 Moshi 卡片或 ntfy。
4. done 后验收、`done-task` 收尾。
5. 宿主偶尔要重启：`fdesetup authrestart`，等自动登录起好 server 后再连（K.4）。
6. 需要点弹窗：`open vnc://mac-mini`（L）。
