# 05 自动化与控制层：不开完整远程桌面，从 laptop 驱动宿主 Mac 的 GUI 与应用

> 场景：laptop（日常机）+ 宿主 Mac（Apple silicon，macOS 26），宿主上 herdr 跑大量 agent，已可经 SSH/Tailscale 访问。目标是从 laptop 的热键、Raycast 或 agent 触发宿主动作：打开应用、点权限弹窗、跑 Shortcut、截图、聚焦窗口、重启服务。
> 调研日期 2026-09-24。标「本地手册」的条目出自 [herdr 完整实施手册](../../../agents/herdr/herdr-完整实施手册-最终版.md)，不是网上来源。
> 贯穿全文的核心问题：**SSH 会话不在 GUI（Aqua）会话里**，而且 TCC 权限记在谁头上取决于进程从哪条链路启动。

---

## Q1. SSH 会话与 GUI（Aqua）会话的分界：哪些命令在 SSH 里能直接用，哪些需要 `launchctl asuser`、GUI 会话里的助手，或放进 GUI 启动的进程（例如 Terminal.app 拉起的 herdr pane）

### Takeaway
SSH 登录落在 launchd 的 Background 域（`user/<uid>`），不在 Aqua 域（`gui/<uid>`）。所以凡是要找 WindowServer、Keychain、GUI 应用或触发 TCC 弹窗的命令，在 SSH 里都可能出问题。可靠的做法有三种：(a) `launchctl asuser <uid> …` 把命令投进 GUI 会话，前提是有人已在 GUI 登录；(b) 放进 GUI 会话里常驻的进程执行，比如 Terminal.app 拉起的 herdr pane，或 Hammerspoon、Keyboard Maestro、BTT 等守护应用；(c) 提前把 TCC 授给 SSH 链路上的负责进程。无头环境里弹窗根本出不来，所以授权必须在到场或屏幕共享时一次性做完。

### Cited Findings
- SSH 会话不在 GUI（Aqua）的 launchd 命名空间里，直接跑 `osascript` 可能看不到 iTerm 这类 GUI 应用。GUI Terminal 与 SSH 的真正分界是 launchd 域：Aqua（`gui/<uid>`）对 Background（`user/<uid>`）。用 `launchctl managername` 可以查看当前会话属于哪个域。— [the KodeLab: macOS GUI Terminal vs. SSH Sessions](https://thekodelab.com/en/posts/macos-gui-terminal-vs-ssh-session/)（全文抓取失败，依据搜索摘要）
- `launchctl asuser $(id -u) osascript …` 会重新进入 GUI 会话。如果当前**根本没人在 GUI 登录**，`asuser` 找不到目标 GUI 会话，命令会失败。— [the KodeLab](https://thekodelab.com/en/posts/macos-gui-terminal-vs-ssh-session/)（搜索摘要）
- 只用 POSIX 的 setuid/setgid 不够：macOS 的用户环境还包括特定的 Mach bootstrap 子集、audit session 等，想要完整的用户身份只能走 launchd，例如 `launchctl asuser "$uid" /path/to/cmd`。以 root 执行 `open`、`osascript`、`defaults` 等命令时都需要这样做。— [Scripting OS X: Demystifying root, Part 3](https://scriptingosx.com/2018/04/demystifying-root-on-macos-part-3-root-and-scripting/)
- `launchctl asuser` 不会建立新的 shell 环境，**不能依赖环境变量，尤其是 PATH**，要写绝对路径。— [Scripting OS X](https://scriptingosx.com/2018/04/demystifying-root-on-macos-part-3-root-and-scripting/)
- `asuser` 在 `launchctl` 里被列为 deprecated，但目前没有替代品（2018 年的说法，至 2026 仍被引用）。— [Scripting OS X](https://scriptingosx.com/2018/04/demystifying-root-on-macos-part-3-root-and-scripting/)
- 取当前控制台用户：`echo "show State:/Users/ConsoleUser" | scutil | awk '/Name :/ && ! /loginwindow/ { print $3 }'`。— [Scripting OS X](https://scriptingosx.com/2018/04/demystifying-root-on-macos-part-3-root-and-scripting/)
- **macOS Tahoe 实例**：在 SSH 里直接执行 app 包内的二进制，窗口会出现，但应用不进 Dock，也没有菜单栏，**收不到键盘事件**（鼠标正常）。原因是应用只有在用户会话里才能正常工作。建议改用 `open /Applications/Pages.app` 这类 bundle 路径，交给 LaunchServices 启动。— [Apple Developer Forums #803553「Macos Tahoe issue launching apps through SSH」](https://developer.apple.com/forums/thread/803553)（全文抓取被拦截，依据搜索摘要）
- Apple 论坛另有专帖讨论「经 SSH 与经 LaunchAgent 访问 WindowServer 等 GUI 服务」的差异。— [Apple Developer Forums #765060](https://developer.apple.com/forums/thread/765060)（未能抓取正文）
- **Keychain**：SSH 会话拿不到已解锁的 login Keychain。从 SSH 拉起的 herdr-server 及其所有 pane 都会继承这个问题，表现为 agent 反复要求登录、`security` 报 `User interaction is not allowed`。由 Terminal.app（GUI 会话）启动的 server，其 pane 继承 GUI 会话权限。实用做法：`ssh mac-mini 'herdr pane run w1:p2 "<cmd>"'`，借 GUI pane 执行需要 GUI 或 Keychain 的命令。— 本地手册 §5.5.1、§5.9.2（[herdr 完整实施手册](../../../agents/herdr/herdr-完整实施手册-最终版.md)）
- macOS 15 起，Virtualization.framework 启动 macOS 客体时要求宿主 login.keychain 已解锁，无头 SSH 下是锁住的，需要先 `security unlock-keychain`。这是「SSH 缺 GUI 会话状态」的又一例。— [Eugene Petrenko, 2026-07-16](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- TCC 受保护目录：`ssh mac-mini 'ls ~/Documents'` 报 `Operation not permitted`。解决办法是在「完全磁盘访问」中打开「远程登录」和「终端」。— 本地手册 §5.4

### Inferences
- **各命令的 SSH 兼容性（综合判断，按风险排序）**：
  - 基本不依赖 GUI、SSH 直接可用：`pmset -g`、`caffeinate`、`shutdown`（需要 sudo）、`fdesetup`、`launchctl kickstart`（重启服务）、herdr CLI、AeroSpace 或 yabai 的 socket CLI（见 Q5）。
  - 通常可用，但依赖「有人在 GUI 登录」：`open -a App`、`open url`（走 LaunchServices，Tahoe 论坛帖也推荐这样启动）。
  - 需要 GUI 会话或 TCC，SSH 里容易失败或弹窗无人处理：`osascript` 控制应用（Automation）、System Events UI 脚本（Accessibility）、`screencapture`（Screen Recording）、`cliclick`（Accessibility）、`security` 读 Keychain、`shortcuts run`（部分动作）。
  - 最稳的执行位置：Terminal.app 启动的 herdr pane。此时 TCC 的「负责进程」是 Terminal，只要给 Terminal 授一次 Accessibility、Screen Recording 和 Automation，从 laptop 用 `herdr pane run` 投递命令即可复用这些授权。这是把本地手册 Keychain 场景的做法推广到 TCC 的推断，尚未实测。
- TCC 按「负责进程」（responsible process）归属授权：Terminal 里启动的子进程算在 Terminal 头上，SSH 链路上的子进程算在 `sshd-keygen-wrapper` 或 `sshd-session` 头上（见 Q2）。这是基于 Q2 引用材料与一般 TCC 行为的推断。
- `launchctl asuser` 需要 root，还是对自身 uid 免 sudo 即可，各来源写法不一（KodeLab 示例未加 sudo，Scripting OS X 在 root 脚本语境下）。建议按 `sudo launchctl asuser $(id -u) sudo -u $USER <cmd>` 的保守写法先测。

### Gaps
- 未能抓取 Apple 论坛两帖正文（developer.apple.com 被抓取工具拦截），Quinn 等 Apple 工程师的原话与官方推荐方案没有核实。
- 没有找到 macOS 26 上 `launchctl asuser` 是否仍可用、是否需要 root 的权威测试记录。
- `launchctl managername` 在 SSH 与 GUI 下的具体输出（如 `Background` 与 `Aqua`）只来自搜索摘要，没有逐字核实。

## Q2. `osascript`、`shortcuts run`、`open -a`、`screencapture` 经 SSH：权限与可用性（macOS 15 到 26）

### Takeaway
`screencapture` 走 SSH 时，没有 Screen Recording 授权就只会拿到**黑帧**。授权要给 SSH 链路上的负责进程：旧版是 `/usr/libexec/sshd-keygen-wrapper`，Sequoia 起有时是 `com.apple.sshd-session`。由于无头时弹窗出不来，最稳的做法是改在 GUI 会话里（herdr pane 或守护应用）截图。`shortcuts run` 在 SSH 下的行为没有找到权威说明，建议同样放进 GUI 会话执行。

### Cited Findings
- 没有 TCC.db 中的 Screen Recording 授权时，`screencapture` 经 SSH 返回**黑帧**。在 macOS 15 以上的无头会话里，能修复它的授权弹窗**永远不会出现**。— [Eugene Petrenko, 2026-07-16](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- 需要授权的客户端随系统版本漂移：历史上是 `/usr/libexec/sshd-keygen-wrapper`；Sequoia 引入 OpenSSH 9.8 的 sshd 拆分后，有时变为 `com.apple.sshd-session`。作者在 VM 场景下把两者都预写进 TCC.db，这要求关闭 SIP 才能写入，**不适用于日常宿主**。— [Eugene Petrenko](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- macOS 15 以上即使授权了，截屏时仍会**周期性弹出**「请求绕过系统私密窗口选择器」对话框，需要自动检测并关闭。— [Eugene Petrenko](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- 有用户在 macOS 15 上把 sshd-keygen-wrapper 同时加进 Accessibility 和「屏幕与系统录音」，新 SSH 会话仍会弹窗。— [Apple Developer Forums #764789「Screen Capture on Mac 15 not working through SSH」](https://developer.apple.com/forums/thread/764789)（依据搜索摘要）
- sshd-keygen-wrapper 是 macOS 自带组件，在经 SSH 连入时出现，用于隐私保护归属。— [macReports](https://macreports.com/what-is-sshd-keygen-wrapper-on-mac/)
- `shortcuts` CLI 基本用法：`shortcuts run "Combine Images"`，名字含空格时加引号或转义。— [Apple Shortcuts 用户指南（Run shortcuts from the command line）](https://support.apple.com/en-ng/guide/shortcuts-mac/apd455c82f02/mac)
- macOS Ventura 13.2 起，非沙盒应用用 Process 调起 shortcuts 会失败，除非给该软件「完全磁盘访问」（开发者论坛报告）。— [Apple Developer Forums #724134](https://developer.apple.com/forums/thread/724134)（依据搜索摘要）
- 有报告称，即使开了「允许运行脚本」，含脚本动作的快捷指令仍报「your Shortcuts security settings don't allow you to run scripting actions」。— [Apple Developer Forums #689436](https://developer.apple.com/forums/thread/689436)（依据搜索摘要）
- 本地手册已要求：隐私与安全性 → 自动化 → 允许「终端」控制需要的应用，`osascript` 会用到。— 本地手册 §5.1 到场清单
- 通过 Terminal 打开宿主 herdr 的写法：`osascript -e 'tell application "Terminal" to do script "herdr --remote mac-mini"'`（在 laptop 本机执行）。— 本地手册 §5.8.2

### Inferences
- **截图的推荐路径**：`ssh mac-mini 'herdr pane run <GUI-pane> "screencapture -x /tmp/s.png"' && scp mac-mini:/tmp/s.png .`。这里复用的是 Terminal 的 Screen Recording 授权，要在到场或屏幕共享时先在 Terminal 里跑一次 `screencapture`，把授权点掉。也可以改用 Hammerspoon、Peekaboo 等已授权的常驻应用来截。
- 若坚持走纯 SSH：到场时在「屏幕与系统录音」和「辅助功能」里用「+」手动加入 `/usr/libexec/sshd-keygen-wrapper`（按 ⌘⇧G 输入路径），然后在 Tahoe 上验证是否还需要 `sshd-session`。对日常宿主**不要为此关闭 SIP**。
- `shortcuts run` 依赖 Shortcuts 的后台服务与用户会话，建议放进 GUI pane，或用 `launchctl asuser` 执行；含「运行 Shell 脚本」「AppleScript」等动作的快捷指令还要在 Shortcuts 设置 → 高级中打开允许脚本。以上是推断，尚未实测。
- `osascript` 在 SSH 里第一次控制某个应用时会触发 Automation 弹窗，无人点击就会卡住或报 -1743（未授权）。应在 GUI 会话里先把常用的「终端 → Finder、System Events、Keyboard Maestro Engine 等」组合授权一遍。

### Gaps
- 没有找到 Apple 官方或可靠实测说明 `shortcuts run` 在纯 SSH（Background 域）下能否执行，以及哪些动作会失败。
- macOS 26 上 Screen Recording 授权到底应给 `sshd-keygen-wrapper` 还是 `sshd-session`，没有 Tahoe 的明确实测。
- macOS 26 是否保留 macOS 15 的「周期性重新确认录屏权限」行为，只有上文 VM 作者的一句概括，没有 Apple 文档。

## Q3. Remote Apple Events（远程应用脚本，`eppc://`）：2026 年状态、安全、能否走 Tailscale

### Takeaway
这项功能在 2026 年仍然存在且有文档：系统设置 → 通用 → 共享 → 远程应用脚本，Apple 帮助页覆盖到最新系统，监听 TCP 3031，用用户名和密码认证。它能用 `tell application "Finder" of machine "eppc://user@host"` 直接驱动对端应用，但也是公认的横向移动手段（Talos，2026-04）。它走普通 TCP，理论上可经 Tailscale IP 使用。对本场景，已有 SSH 加 osascript 可以做同样的事，**不建议开启**。

### Cited Findings
- 开启路径：Apple 菜单 → 系统设置 → 通用 → 共享 → 「远程应用脚本」旁的 ⓘ → 打开，再在「允许访问」中选「所有用户」或「仅这些用户」（可加本机用户或网络用户与群组）。该帮助页标注覆盖范围为「macOS 27 Golden Gate 至 Catalina 10.15」。— [Apple Support: Allow remote application scripting on Mac](https://support.apple.com/en-gb/guide/mac-help/mchlp1398/mac)
- eppc 意为 event program-to-program communication，URL 以 `eppc://` 开头，后接 IP 或 DNS 名。— [Apple Support（旧版 10.15 页）](https://support.apple.com/en-nz/guide/mac-help/mchlp1398/10.15/mac/10.15)（依据搜索摘要）；[Apple Developer: SecProtocolType.eppc](https://developer.apple.com/documentation/security/secprotocoltype/eppc)
- 通信走 **TCP 3031**，需要用户名和密码认证，目标机由 **AppleEventsD** 守护进程处理。— [Cisco Talos「Bad Apples」, 2026-04-21](https://blog.talosintelligence.com/bad-apples-weaponizing-native-macos-primitives-for-movement-and-execution/)；[Unit 42: Lateral Movement on macOS](https://unit42.paloaltonetworks.com/unique-popular-techniques-lateral-movement-macos/)（依据搜索摘要）
- Talos 的说法：RAE 被当作 macOS 原生横向移动手段；远程让 System Events 执行 shell 会遇到 -10016 Handler Error，可以借 Terminal.app 做执行代理绕过。建议监控入站 TCP 3031，警惕 `launchd → AppleEventsD → Terminal → sh` 这类进程链；用 MDM 的 `com.apple.RemoteAppleEvents` payload 默认禁用 RAS，并严格管理 TCC「自动化」类别。— [Cisco Talos, 2026-04-21](https://blog.talosintelligence.com/bad-apples-weaponizing-native-macos-primitives-for-movement-and-execution/)
- Apple Remote Desktop 3.10（2025-10-08）新增 macOS Tahoe 26 兼容。— [Wikipedia: Apple Remote Desktop](https://en.wikipedia.org/wiki/Apple_Remote_Desktop)
- Apple 的端口文档（HT6175）列出 Apple 软件使用的 TCP/UDP 端口，包括 eppc。— [Apple Support HT6175（德文版）](https://support.apple.com/de-de/HT6175)（未抓取正文）

### Inferences
- **能否走 Tailscale**：eppc 是普通 TCP（3031），Tailscale 是三层网络，因此用 `eppc://user@mac-mini.<tailnet>.ts.net` 或 `eppc://user@100.x.y.z` 理论上可达。Bonjour 发现（`.local`）跨 Tailscale 不可用，必须写 IP 或 MagicDNS。以上是推断，没有找到实测报告。
- **相对 SSH 加 osascript 没有优势**：`ssh mac-mini osascript -e '…'` 已经能完成同样的应用控制，而且复用了密钥认证与 Tailscale ACL。RAE 反而多开一个用口令认证的监听端口，还是公开的攻击面。所以本场景不建议开启；如果确有需要（例如在 laptop 的 Script Editor 里直接 `tell … of machine`），应只允许特定用户，并用 macOS 防火墙或 Tailscale ACL 把 3031 限制在 tailnet 内。
- `systemsetup -setremoteappleevents on` 是常见的命令行开关（本轮未抓到来源核实）；在较新的 macOS 上 `systemsetup` 本身可能需要终端具有完全磁盘访问。

### Gaps
- 没有找到 eppc 传输是否加密的权威说明，只查到 Keychain 协议类型定义。
- 没有找到 Tailscale 上使用 eppc 的实测。
- 没有找到 macOS 26 是否对 RAE 加了新限制或废弃计划的官方信息；Apple 帮助页仍在更新，暂无废弃迹象。

## Q4. 宿主上的常驻自动化守护应用：Hammerspoon、Keyboard Maestro、BetterTouchTool；laptop 侧的 Raycast、Alfred

### Takeaway
最稳的模式是「宿主上一个已拿到 TCC 授权的 GUI 常驻应用，加一个只绑在 Tailscale 或 localhost 的触发入口，再由 laptop 上的 Raycast 热键或脚本调用」。Hammerspoon 的 `hs.httpserver` 能绑接口、设口令、开 HTTPS；BTT 的 webserver 有 shared secret，默认只监听 127.0.0.1；Keyboard Maestro 的 Remote trigger 和 Public Web trigger **都不需要认证**，要慎用，它的 AppleScript 接口可以经 SSH 调用。Raycast 负责在 laptop 侧把这些入口挂到全局热键上。

### Cited Findings
**Hammerspoon**
- `hs.httpserver.new([ssl],[bonjour])` 创建 HTTP 或 HTTPS 服务器；`setPort()` 指定端口（默认随机）；`setInterface()` 可以绑接口名（如 `en0`）、IP、`localhost` 或 `loopback`，传 nil 表示监听所有接口（默认）；`setPassword()` 提供 Basic Auth，只能设一个口令，不能按路径区分；SSL 使用自签名证书；Bonjour 默认广播；`maxBodySize` 默认 10MB。回调签名为 `(method, path, headers, body)`，返回 `(body, status, headers)`。官方警告运行 HTTP 服务器有潜在危险。— [Hammerspoon docs: hs.httpserver](https://www.hammerspoon.org/docs/hs.httpserver.html)
- `hs` 命令行工具通过 `hs.ipc.cliInstall()` 安装，要求 init.lua 里有 `require("hs.ipc")`。它基于 message port，CLI 充当 remote port，向 Hammerspoon 内的 local port 发消息。— [Hammerspoon docs: hs.ipc](https://www.hammerspoon.org/docs/hs.ipc.html)
- 常见报错有「can't access Hammerspoon message port … is it running with the ipc module loaded?」和「message port was invalidated」。— [GitHub issue #1548](https://github.com/Hammerspoon/hammerspoon/issues/1548)；[hs.m 源码](https://github.com/Hammerspoon/hammerspoon/blob/master/extensions/ipc/cli/hs.m)（依据搜索摘要）

**Keyboard Maestro**
- **Remote trigger**：`https://trigger.keyboardmaestro.com/t/<ID1>/<ID2>?TriggerValue`，经 Stairways 的服务器中转，不依赖本机 web server；v8 起提供；**无认证**，任何知道触发码的人都能从互联网任意位置触发；`TriggerValue` 会进入 `%TriggerValue%`；官方建议只用于「安全」操作（重启服务、启动应用），并说明不保证长期可用。— [KM Wiki: Remote trigger](https://wiki.keyboardmaestro.com/trigger/Remote)
- **Public Web trigger**：本机 web server 使用 HTTP 4490 和 HTTPS 4491；格式为 `https://host:4491/action.html?macro=<UUID>&value=<v>`；**不需要用户名和密码**（反过来说明普通 Web Server 页面是有账号口令的）；同样只建议做安全操作。— [KM Wiki: Public Web trigger](https://wiki.keyboardmaestro.com/trigger/Public_Web)
- AppleScript 接口：`tell application "Keyboard Maestro Engine" to do script "<宏 UUID 或名称>"`。重名时必须用 UUID；宏及其宏组必须启用且处于激活状态；`do script` 要等宏执行完才返回。可以从 shell 用 `osascript` 调用。— [KM Wiki: Scripting](https://wiki.keyboardmaestro.com/manual/Scripting)；[KM Forum: Call KBM Macro from the Shell with osascript](https://forum.keyboardmaestro.com/t/call-kbm-macro-from-the-shell-with-osascript/20686)（依据搜索摘要）

**BetterTouchTool**

## Q5. 基于 Accessibility 的 CLI 工具：`cliclick`、`yabai` 与 `aerospace` 窗口管理、`displayplacer`

### Takeaway
`cliclick` 负责点击和键入，需要 Accessibility，授权要给调用它的宿主进程（Terminal 或 SSH 链路），用法上有修饰键卡住的坑。AeroSpace 的 CLI 通过 `/tmp` 下的 Unix socket 和 App 通信，因此 SSH 里调用多半可行，窗口聚焦可以直接 `ssh mac-mini aerospace focus …`。`displayplacer` 用来固定分辨率和布局，在无头宿主或需要稳定截图坐标时有用。

### Cited Findings
- cliclick 的命令：`c:x,y` 点击，`m:x,y` 移动，`t:text` 键入，`kp:key` 按键，`kd:`/`ku:` 按下或松开修饰键，`w:ms` 等待，`p` 打印坐标。支持 macOS 10.15 起，建议用 Homebrew 安装。**必须**在「辅助功能」里给 Terminal 或 iTerm 授权，否则无效并在 stderr 警告。不能操作登录窗口。— [GitHub: BlueM/cliclick](https://github.com/BlueM/cliclick)
- 坑：`kp:` 只接受命名键，不接受字母，所以 `kd:cmd kp:a ku:cmd` 会在 `a` 处报错，而 Cmd 一直按着不放，后续键入全部变成快捷键，一次测试因此触发了注销对话框。修正方法：每条命令后无论成败都释放 `cmd,ctrl,alt,shift`；字母加修饰键写成 `kd:cmd t:a ku:cmd`。— [Eugene Petrenko](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- HiDPI：截图的像素坐标是逻辑坐标的 2 倍，点击前要除以 2。作者用 `displayplacer` 在 macOS 26 上固定显示模式。— [Eugene Petrenko](https://jonnyzzz.com/blog/2026/07/16/a-real-macos-desktop-for-a-linux-agent/)
- AeroSpace 的 CLI 与 App 通过 Unix socket 通信：发布版为 `/tmp/bobko.aerospace-${USER}.sock`；握手后使用 4 字节小端长度前缀加 UTF-8 JSON 帧，供自定义客户端集成。— [AeroSpace Guide](https://nikitabobko.github.io/AeroSpace/guide)；[AeroSpace Commands](https://nikitabobko.github.io/AeroSpace/commands)（依据搜索摘要）
- displayplacer 相当于 macOS 上的 XRandR：`displayplacer list`、`displayplacer "id:<id> res:WxH origin:(x,y) degree:0"`，也可以 `enabled:false` 关闭某块屏或设置镜像；用 `brew install displayplacer` 安装。— [GitHub: jakehilborn/displayplacer](https://github.com/jakehilborn/displayplacer)

### Inferences
- AeroSpace 和 yabai 的「窗口聚焦、移动」CLI 本身只是向 GUI 会话里常驻的 App 发 socket 消息，真正执行动作的是已拿到 Accessibility 的 App。所以经 SSH 调用 `aerospace focus --window-id …`、`aerospace workspace 2`、`aerospace list-windows --all` 大概率可行，只要 `$USER` 一致、`/tmp` 下的 socket 可访问。这是基于 socket 架构的推断，未实测；是宿主上「聚焦某窗口」最干净的远程方式。
- yabai 同样用 `/tmp` 下的 Unix socket（来自训练知识，本轮未核实）。它的部分高级功能（spaces 操作等）要求部分关闭 SIP，**宿主不建议关闭 SIP**；只做聚焦和移动时 AeroSpace 不需要动 SIP，更合适。
- 在宿主上，cliclick 最好只在 GUI pane 里用（复用 Terminal 的 Accessibility）；如果要用它点权限弹窗，先截图定位坐标，并注意 2 倍缩放。更稳的点弹窗方式是 Hammerspoon 或 AppleScript 按 AX 元素名点击，不用坐标。

### Gaps
- yabai 关于 SIP 的 wiki 页未能抓取，macOS 26 上 yabai 的 SIP 要求和兼容性没有核实。
- cliclick 最新版本号与发布日期、Apple silicon 上的已知问题，只有 README 里一句「may have issues」。
- displayplacer 在 macOS 26 上是否仍维护，最后发布日期没有查到。

## Q6. 让 AI agent 操作宿主桌面：Claude computer use、macOS 自动化 MCP（Peekaboo、AppleScript 或 JXA 类）与安全

### Takeaway
2026 年有两条成熟路线。(1) Anthropic 官方：Claude Desktop 和 Claude Code 的 computer use，macOS 研究预览，需要 Pro 或 Max；需要 Accessibility 和 Screen Recording；按应用逐个授权，浏览器只能看、终端只能点；2026-09 起 macOS 上可以**后台运行**。(2) 开源 MCP：Peekaboo（截图、看图、点击、键入，macOS 15 以上，内置 Bridge Host 作为 TCC 代理）以及 AppleScript 或 JXA 类 MCP。宿主场景下最实用的做法，是让 herdr 里的 agent 挂上 Peekaboo 或 AppleScript MCP，并在 GUI 会话里运行，以复用 TCC 授权。屏幕内容带来的提示注入是最大风险。

### Cited Findings
**Claude computer use（官方）**
- 在 Claude Code Desktop 中：macOS 和 Windows 上是研究预览，**需要 Pro 或 Max**，Team、Enterprise 和 Linux 不可用，且 Desktop 应用必须在运行。开启方式为 Settings → General → Computer use；macOS 还需授予 **Accessibility**（点击、键入、滚动）和 **Screen Recording**（看屏幕）。— [Claude Code Docs: Desktop](https://code.claude.com/docs/en/desktop)
- 每个应用第一次使用时会弹出授权，可选「Allow for this session」，由 Dispatch 发起的会话授权 30 分钟。访问分级：浏览器和交易平台只能看，终端和 IDE 只能点（不能键入），其余应用可完全控制。终端、Finder、系统设置会额外警告。可以配置「Denied apps」。— [Claude Code Docs: Desktop](https://code.claude.com/docs/en/desktop)
- 工具优先级依次为 Connectors、Bash、Claude in Chrome、iOS Simulator pane，最后才是 computer use。支持矩阵列出：本地会话和「SSH sessions」支持，云会话和 WSL 不支持。官方安全提示：computer use 在真实桌面上运行，信任边界不同于沙盒 Bash；Claude 会标记屏幕内容里可能的提示注入；Bypass permissions 模式只应在容器或 VM 中使用。— [Claude Code Docs: Desktop](https://code.claude.com/docs/en/desktop)
- 2026-09-02：Anthropic 把 Claude Cowork 和 Claude Code 的 computer use 升级为可在 Mac **后台**运行，不抢占用户的指针和键盘，仅限 macOS，Pro 或 Max。— [9to5Mac, 2026-09-02](https://9to5mac.com/2026/09/02/anthropic-upgrades-claude-codes-computer-use-to-run-in-the-background-on-mac/)；[AlternativeTo, 2026-09](https://alternativeto.net/news/2026/9/claude-can-work-in-background-windows-on-macos-desktops/)
- macOS 15 以上默认在后台窗口工作，但仍需授权；投资、交易、加密货币类敏感应用默认被屏蔽。— [Claude Help Center: Let Claude use your computer in Cowork](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork)（依据搜索摘要）

**Peekaboo（openclaw/Peekaboo，原 steipete）**
- 它是 macOS CLI 加可选 MCP 服务器：截图、`see`（UI 元素分析）、`click`、`type`、`press`、`scroll`、`drag`、`set-value`，还能操作应用、窗口、菜单、Dock、对话框和 Spaces。需要 **Screen Recording** 和 **Accessibility**。CLI 和 App 要求 **macOS 15 以上**，npm MCP 包要求 Node 22 以上。可通过 `brew install steipete/tap/peekaboo` 或 `npx @steipete/peekaboo mcp` 安装，接入 Codex、Claude Code、Cursor。仓库已从 steipete 迁到 openclaw，当前版本 4.5.0，MIT 许可。— [GitHub: openclaw/Peekaboo](https://github.com/openclaw/Peekaboo)

**其他 macOS 自动化 MCP**
- steipete/macos-automator-mcp：通过 MCP 执行 AppleScript 和 JXA。— [GitHub](https://github.com/steipete/macos-automator-mcp)
- adamrdrew/applescript-mcp：让 LLM 通过 AppleScript 控制应用、文件、音乐、消息等。— [GitHub](https://github.com/adamrdrew/applescript-mcp)
- CursorTouch/MacOS-MCP：轻量的 macOS computer use MCP，基于 Accessibility API 操作 UI 元素。— [GitHub](https://github.com/CursorTouch/MacOS-MCP)（依据搜索摘要）

### Inferences
- **宿主落地建议**：在 Terminal.app 启动的 herdr pane 里运行的 Claude Code 或 Codex，加上 Peekaboo MCP 或 macos-automator-mcp，TCC 归属是 Terminal（或 Peekaboo.app 经 Bridge），给 Terminal（或 Peekaboo.app）授一次 Accessibility、Screen Recording 和 Automation 即可。laptop 上通过 Raycast Herdr 扩展或 `herdr-mm` 给这个 agent 发指令，例如「点掉 Xcode 的权限弹窗并截图给我」。这样不用开屏幕共享，也不用在 SSH 链路上授任何 TCC。

## Q7. herdr socket 转发与 Raycast Herdr 扩展作为控制面（简述）

### Takeaway
用户已具备这套能力。`ssh -L` 把宿主的 `~/.config/herdr/herdr.sock` 转发到 laptop 的 `/tmp/herdr-mac-mini.sock`，本地 herdr CLI 和 Raycast Herdr 扩展就能直接操作宿主的 workspace 和 agent。配合 `herdr pane run`，它也是把「GUI 或 TCC 敏感命令」投递到宿主 GUI 会话的最短路径。

### Cited Findings
- herdr 的通信走本地 Unix socket，协议是按行分隔的 JSON。默认 socket 为 `~/.config/herdr/herdr.sock`，命名 session 为 `~/.config/herdr/sessions/<name>/herdr.sock`，选择优先级依次是 `--session`、`HERDR_SOCKET_PATH`、`HERDR_SESSION`、默认值。— 本地手册 §1.6
- `~/bin/herdr-mm` 脚本：socket 不存在或不通时，执行 `ssh -o BatchMode=yes -fnNT -L "$sock:$rhome/.config/herdr/herdr.sock" mac-mini` 重建隧道，然后 `HERDR_SOCKET_PATH="$sock" exec herdr "$@"`。Raycast Herdr 扩展的「Herdr Binary」填 `~/bin/herdr-mm` 后，整个扩展就作用于宿主（只能指定一个 Binary）。— 本地手册 §5.8.3
- 配对 moshi-hook 这类必须在 GUI 会话里完成的操作，用 `herdr pane split` 加 `herdr pane run w1:p2 "<cmd>"` 加 `herdr pane read … --source visible`，借 GUI pane 执行。— 本地手册 §5.9.2
- 宿主上的 server 不要交给 launchd 直接托管，要由 Terminal 在登录时拉起（Terminal 描述文件里「启动时运行命令」填 `herdr`，并把「终端」加入登录项）。— 本地手册 §5.5.1–5.5.2

### Inferences
- 可以在宿主上常驻一个名为 `gui-ops` 的 herdr pane，专门接收「GUI 动作」命令（`open -a`、`screencapture`、`osascript`、`shortcuts run`、`cliclick`），laptop 用 Raycast 脚本 `herdr-mm pane run <gui-ops> "…"` 触发。这样得到的是一个带授权、在 GUI 会话里、走 SSH 或 Tailscale 认证的执行通道，其他技术（Hammerspoon HTTP、KM）可以作为补充。
- 风险：任何能访问这个 socket 的人都能在宿主 GUI 会话里执行任意命令，包括借 Terminal 的 TCC 授权截屏或点击，等同于完全控制宿主。laptop 上的 `/tmp/herdr-*.sock` 应保持 0600（OpenSSH 的 `StreamLocalBindMask` 默认 0177）。

### Gaps
- herdr 0.9 的 socket API 是否支持「只读」或按动作鉴权，本地手册没有提及。

## Q8. 远程电源与会话控制：`pmset`、`caffeinate`、`fdesetup authrestart`、Tahoe 的 SSH 解锁 FileVault、`shutdown -r`、经 Tailscale 的 Wake-on-LAN

### Takeaway
宿主应该「永不睡眠，只关显示器，唤醒以供网络访问，断电后自动开机」。需要重启时，开着 FileVault 就用 `sudo fdesetup authrestart`（Apple silicon 上是 Secure Enclave 的一次性令牌）。**macOS 26 新增的**「重启后经 SSH 解锁 FileVault」（仅 Apple silicon，需要开启远程登录）是 2026 年最重要的变化，但解锁后 GUI 是否会自动登录需要实测（它决定 herdr 能否自启）。Wake-on-LAN 的魔术包是二层报文，Tailscale（三层）转发不了，需要局域网里一台常开设备代发。

### Cited Findings
- `pmset sleepnow`（立即睡眠）和 `displaysleepnow`（立即关显示器）在 man 页中已标为 deprecated，推荐改用 `caffeinate`。`caffeinate -u` 声明用户活动：显示器关着时会把它点亮并阻止空闲熄屏，不加 `-t` 时默认持续 5 秒。`-d`、`-i`、`-s` 分别阻止显示器睡眠、系统空闲睡眠、系统睡眠（`-s` 仅在接电源时有效）。— [pmset(1)](https://keith.github.io/xcode-man-pages/pmset.1.html)；[SS64: caffeinate](https://ss64.com/mac/caffeinate.html)（依据搜索摘要）
- 宿主设置：`sudo pmset -a sleep 0 disksleep 0 womp 1 autorestart 1`、`displaysleep 10`，对应「显示器关闭时防止自动睡眠」「唤醒以供网络访问」「断电后自动启动」三项；用 `pmset -g` 核对；临时防睡用 `caffeinate -s <命令>`。— 本地手册 §5.2.3
- `sudo fdesetup authrestart -delayminutes 0` 立即重启，并跳过这一次的 FileVault 解锁。T2 和 Apple silicon 上，authrestart 由 **Secure Enclave** 处理，令牌**只能用一次**。它绕不过系统更新。— [macuser.org.uk, 2026-07-22](https://macuser.org.uk/2026/07/22/how-to-remotely-reboot-a-filevault-protected-mac-without-entering-a-password/)；[Eclectic Light: authenticated restart and fdesetup](https://eclecticlight.co/2023/02/20/macos-13-2-1-authenticated-restart-and-fdesetup/)（依据搜索摘要）
- 限制：只对这一次重启有效；断电或拔电后仍需要 FileVault 登录；重启失败会导致无法远程访问。关闭 FileVault 能保证任何重启后都可访问，但有人拿到机器后可以进 recoveryOS 读取数据。— [Macworld, 2025-01-23](https://www.macworld.com/article/2568036/how-to-manage-filevault-to-maintain-remote-access-to-your-mac.html)
- 先用 `fdesetup supportsauthrestart` 检查，输出 `true` 才能用；关闭 FileVault 且开了自动登录时，可以直接 `ssh mac-mini 'sudo shutdown -r now'`。— 本地手册 §5.2.4、§7.3
- **macOS Tahoe 26 新功能**：开启「远程登录」后，重启后的 Mac 在 FileVault 解锁**之前**就接受 SSH 口令认证，可以借此远程解锁数据卷。说明见 `man apple_ssh_and_filevault`。— [Apple: What's new for enterprise in macOS Tahoe 26](https://support.apple.com/en-us/124963)；[apple_ssh_and_filevault(7)](https://keith.github.io/xcode-man-pages/apple_ssh_and_filevault.7.html)
- 机制：OpenSSH 的配置文件放在加密的数据卷上，所以解锁前只能用**口令**认证，公钥不可用。解锁后 macOS 会**短暂断开 SSH**，等数据卷挂载、依赖它的服务启动之后才能重新连上。— [apple_ssh_and_filevault(7)](https://keith.github.io/xcode-man-pages/apple_ssh_and_filevault.7.html)
- 要求：**仅限 Apple silicon**，macOS Tahoe 或更新，已开启 FileVault 和 SSH，使用有权解锁 FileVault 的本地账号和口令。解锁后 SSH 连接会被自动关闭，之后可以重新连接。— [Der Flounder, 2025-10-11](https://derflounder.wordpress.com/2025/10/11/unlocking-filevault-via-ssh-on-macos-tahoe/)
- 有使用者报告，Wi-Fi 下 SSH 解锁不可用，改接以太网后可靠；这个功能要求你能从同一网络或自己的 VPN 到达该 Mac，不面向公网。— [Jeff Geerling](https://www.jeffgeerling.com/blog/2025/you-can-finally-manage-macs-filevault-remotely-tahoe/)；[DeepakNess](https://deepakness.com/raw/remote-filevault-unlock-macos-tahoe/)（依据搜索摘要，未核实具体出自哪篇）
- **WoL 加 Tailscale**：Tailscale 工作在三层，WoL 魔术包是二层广播，即使开了 subnet router 也转发不了。可行方案：局域网里放一台常开设备（Raspberry Pi 等），用 `etherwake` 并经 Tailscale SSH 远程触发；或部署 UpSnap Web 面板（可以做成 Tailscale sidecar 节点，用 MagicDNS 访问）。前提是目标设备本身已正确配置 WoL。— [Tailscale Blog: Wake-on-LAN with Tailscale + UpSnap](https://tailscale.com/blog/wake-on-lan-tailscale-upsnap)
- 开源项目 tailscale-wakeonlan 提供 tailnet 内的 Web UI，可以从任意 tailnet 设备唤醒局域网设备。— [GitHub: andygrundman/tailscale-wakeonlan](https://github.com/andygrundman/tailscale-wakeonlan)
- Tailscale SSH **服务端**在 macOS 上只支持开源 `tailscaled` 版本，App Store 版和 Standalone GUI 版不行。ACL 的 `ssh` 规则支持 `accept`，以及需要重新做 IdP 认证的 `check`（默认 12 小时）。— [Tailscale Docs: Tailscale SSH](https://tailscale.com/docs/features/tailscale-ssh)；[Tailscale Docs: macOS variants](https://tailscale.com/docs/concepts/macos-variants)
- 本地手册建议：宿主装开源 `tailscaled`（`brew install tailscale`），好处是无人登录时也运行、支持 Tailscale SSH；并关闭节点密钥过期。— 本地手册 §3.2、§5.3

### Inferences
- **宿主重启后的链路（Tahoe，FileVault 开启）**：`ssh mac-mini 'sudo shutdown -r now'` 后，经局域网或 Tailscale 用口令 SSH 解锁 FileVault，等 SSH 恢复。此时如果**没有**进入 GUI 登录，herdr 不会自启（它依赖 Terminal 随登录启动），要用屏幕共享登录一次，或者评估解锁后能否触发自动登录（FileVault 与自动登录互斥，见本地手册 §5.2.4）。能否免到场，关键就在这一点。
- **Tailscale 在 FileVault 解锁前能否使用**：开源 `tailscaled` 以系统 daemon 运行，但它的状态和配置很可能在数据卷上（例如 `/Library/Tailscale` 或 `/var/db`），解锁前大概率还没启动。因此 SSH 解锁 FileVault **很可能只能在局域网里做**，远程时要靠局域网内的一台跳板机（如装 etherwake 的 Pi，也能兼做 WoL）。这是推断，需要实测。
- 优先用 `sudo fdesetup authrestart` 做计划内重启，它不依赖 SSH 解锁，重启后直接进入已解锁状态并执行自动登录链路（Apple silicon 的一次性令牌）。SSH 解锁留给意外重启和断电恢复兜底。
- Mac 的 WoL 一般只能从睡眠唤醒，不能从关机状态唤醒（训练知识，未核实）。所以宿主策略应是永不关机、`autorestart 1`，WoL 只作为「睡眠」这种意外情况的兜底。
- 常用的远程会话与电源命令（均可经 SSH 执行）：`caffeinate -u -t 5`（点亮显示器）、`pmset displaysleepnow`（已 deprecated 但仍可用）、`pmset -g log | grep -i sleep`（排查夜间掉线）、`sudo launchctl kickstart -k system/com.openssh.sshd` 或 `gui/$(id -u)/<label>`（重启服务）、`sudo shutdown -r now`。

### Gaps
- 没有找到经 SSH 解锁 FileVault 之后，GUI 会自动登录还是停在登录窗口的权威说明。这直接决定 herdr 能否自启，是最关键的未决问题。
- 没有找到 Tailscale（开源 `tailscaled`）在 FileVault 解锁前是否已运行的官方说明。
- 「Wi-Fi 下 SSH 解锁不可用」只是个别作者的报告，原因（Wi-Fi 凭据存在数据卷上？）没有得到 Apple 确认。
- Apple silicon Mac 从关机状态是否支持 WoL，本轮没有找到权威来源。
